ORDER API DOCUMENTATION

Scope
- This file documents the implemented API surface for the order domain in this branch.
- This branch now includes the order entities, enums, repositories, Flyway schema, DTOs, controllers, service workflows, validation, pricing recalculation, reporting endpoints, and public QR ordering endpoints.
- External payment gateway settlement and external KDS dispatch integrations are still not implemented. Payment-related endpoints currently manage internal order and payment status only.
- All ids are UUID values unless noted otherwise.
- Orders should never be hard-deleted in production. Use cancel, void, close, reopen, transfer, and event endpoints instead.

Recommended request shapes

Create order
- tableId: uuid, optional
- reservationId: uuid, optional
- customerId: uuid, optional
- orderNumber: string, optional if generated server-side, max 50
- currency: string, optional if derived from restaurant, must be ISO 4217 code
- orderType: OrderType, optional
- source: OrderSource, optional
- guestCount: integer, optional, min 1
- notes: string, optional
- items: array<CreateOrderLineItem>, optional
- discounts: array<CreateOrderDiscount>, optional

Create order line item
- menuItemId: uuid, required
- variantId: uuid, optional
- quantity: integer, required, min 1
- notes: string, optional
- options: array<CreateOrderItemOption>, optional

Create order item option
- optionItemId: uuid, required
- quantity: integer, optional, min 1
- notes: string, optional

Create order discount
- name: string, required, max 100
- discountType: OrderDiscountType, required
- discountValue: decimal, required, min 0
- reason: string, optional

Patch order header
- branchId: uuid, optional
- tableId: uuid, optional
- reservationId: uuid, optional
- customerId: uuid, optional
- orderNumber: string, optional, max 50
- currency: string, optional, must be ISO 4217 code
- orderType: OrderType, optional
- source: OrderSource, optional
- status: OrderStatus, optional
- guestCount: integer, optional, min 1
- openedAt: datetime, optional
- items: array<CreateOrderLineItem>, optional
- discounts: array<CreateOrderDiscount>, optional
- notes: string, optional


Recommended response sections
- order header: id, orderNumber, branch, table, reservation, customer, source, type
- operational status: status, fulfillmentStatus, paymentStatus, openedAt, closedAt
- pricing summary: subtotal, discountTotal, taxTotal, serviceChargeTotal, total, currency
- line items: item snapshot, variant snapshot, quantity, totals, status, options
- discounts: name, type, value, amountApplied, appliedBy, createdAt
- timeline: eventType, note, createdBy, createdAt

Implementation notes
- The documented endpoints above are implemented in this branch.
- Payment endpoints manage internal order payment status only. No external PSP or settlement workflow is connected yet.
- Kitchen workflow endpoints update order and line-item states and write order events. No external KDS dispatch adapter is connected yet.
- Public checkout currently records a checkout request and only closes the order when `closeOrder=true` and the order is already in a paid state.
- Public cancel-request cancels the order directly only when it is still unpaid and pending; otherwise it is recorded as a cancellation request note on the order timeline.
- Branch export currently returns a structured JSON export payload of orders for the requested window.
